# Dormant paid workspace fixture

The paid design is OFF by default. `wt serve --local --dev --paid-fixture --addr 127.0.0.1:PORT` enables a per-tab, provider-free UI at `/app/#paid/upgrade/offers` and a link in the local header. Use a new isolated `WINGTHING_DIR`; do not select daily state. Startup rejects the fixture without explicit local/development mode or with local HTTPS, and the server refuses it for roost/login/edge modes. This is a display gate, not an entitlement grant; existing account and relay policy is unchanged.

The source storyboard's upsell switch was planned, with no matching code flag in this base. `paid_fixture` implements the default-OFF review gate. It does not launch public paid offers. Normal startup ignores paid fragment URLs and renders no paid fixture UI.

Upgrade, cloud, billing and later teams share a pure typed fixture contract. UI actions persist only in sessionStorage; review profiles reset Free owner, Pro owner, operator or paired phone scenarios. Explicit fixture payment events advance entitlement; return URLs do not. Saved actions are never auto-executed. Launch IDs bind drafts, reservation precedes boot, stop confirmation settles verified usage, and expired Pro preserves local sessions and device grants. Phone requests only queue input for an approved coordinator template; phone pairing confers no billing, VM, repository or vault management.

The design's proposed prices are $29/month, 20 Standard hours, 10 GB storage and 100 GB outbound. Standard / Large use 1× / 2× compute credit and $0.35 / $0.70 per ready running hour after opt-in. Values are fixture proposals, not approved offers. Extra spend defaults to zero. VM reservations include a 2 minute shutdown buffer; model and egress overage are not admitted in this fixture. BYO provider invoices remain external. Production usage policy, taxes, dunning and retention still require approval and real provider validation.

`node scripts/paid-fixture.mjs --fixture-json` consumes `{ "scenario": "active", "actions": [{"op":"draft","hours":2}] }` on stdin and returns structured fixture state. This deliberate intermediate typed adapter exercises the same contract as the browser. It is not a production CLI/MCP cloud capability. No fixture operation calls a service, sends a message, accepts secret values or writes account billing/entitlements.

Run `make web` for unit tests and the production SPA build. `make test-paid-ui PAID_BASE_URL=http://127.0.0.1:PORT` drives the real built SPA using Chromium; `PAID_SHOTS_DIR` selects a PNG/JSONL output directory. `make test-paid-gate` verifies default-OFF and invalid startup. Native phone UI, production payment/VM/SSO/network enforcement and the storyboard's proposed `wt run --cloud` syntax remain outside this web fixture. Screenshots show web UI at desktop and phone-sized viewports, never native iPhone acceptance.
