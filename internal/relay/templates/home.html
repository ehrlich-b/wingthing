The agent manager for agents (and people)

Wingthing is an open-source (MIT) tool for running coding agents in persistent terminals and supervised tasks on your own machines.

Install wingthing Docs Agent skill {{if .User}}Open app{{else}}Install{{end}}

How a wing owns the work

See patterns · choose a route

One execution machine

A wing owns processes, terminal sessions and run records on its machine. The workspace and provider login must already be there.

Terminal sessions

A session keeps an interactive terminal running after you detach. Reattach from the CLI or an authorized browser route.

Supervised runs

A run has semantic status, events and a final result. Its active process needs the supervising wing; terminal text alone is not a result.

Local state

Sessions, run records and agent homes stay on their wing. Wingthing does not synchronize workspaces, logins or memory between machines.

CLI and MCP

The CLI attaches people to terminals. MCP gives a parent agent typed controls; local stdio connects to an already running wing.

Set the boundaries

Inspect sandbox policy before launch. Control file, network, and environment access.

Install, run, then connect an agent

Install on macOS or Linux. Install and authenticate your provider CLI separately.

curl -fsSL https://wingthing.ai/install.sh | sh

Account-free local terminal

cd /path/to/existing/project
wt egg claude --name research
# Ctrl+B then Q detaches
wt attach research

Local MCP for a parent agent

Start a local-only wing and keep it running before registering stdio. Use the same WINGTHING_DIR in the wing and parent client's MCP process environment (default ~/.wingthing).

wt wing start --local-only
codex mcp add wingthing -- wt mcp stdio --client codex
# or: claude mcp add --scope user wingthing -- wt mcp stdio --client claude

No Wingthing account is required. Restart the parent client and call wingthing_capabilities.

Optional browser routes

A self-hosted roost embeds a wing: wt roost start --https, then open https://localhost:8443. It needs no Wingthing account; shared access needs OAuth, HTTPS and explicit enrollment. The optional hosted browser needs an account that already has hosted-relay access and a wing that permits it before login or opening the app. Browser prerequisites and commands.
